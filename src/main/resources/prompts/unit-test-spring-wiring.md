# Relevant policy: spring-wiring
- Mockito is not Spring: @InjectMocks does not resolve @Value, configuration properties, ApplicationContextAware callbacks or service-locator beans. Before Act, map each reached dependency/configuration read to the EXACT instance/field used by source. A mock with a convenient name is not evidence that production uses it.
- For each source-declared non-final injectable instance field, constructor injection is preferred when a matching constructor exists. Otherwise Spring's ReflectionTestUtils.setField(sut, "exactDeclaredField", value) is valid fixture initialization when spring-test is present. This permits verified private @Autowired/@Value instance fields; it does NOT permit inventing a field or changing business state to defeat an approved assertion. Never assume a setBaseMapper/setCacheService setter exists. Use the exact field name, declared type and values from the supplied application configuration/approved data. Boxed Long expiry values require Long fixtures, not null or an arbitrary Integer. Initialize every scalar used by the reached path, including Redis key prefixes and expiration.
- Inspect helpers before wiring: a getCacheService()-like method may call a static service locator and have NO cacheService field. Either run that locator through its source-confirmed bootstrap, or use an initialized @Spy SUT and doReturn(theSameMock).when(sut).helper() for a helper outside the actual Act method. This is not permission to stub the method being tested, including when that method itself is a lookup/helper. Do not use ReflectionTestUtils to inject a fictitious field matching a mock's name.
- For a source-confirmed ApplicationContextAware helper with a static non-final ApplicationContext field, a mocked ApplicationContext may be installed through its real callback before Act, without starting Spring or using static mocking. Stub context.getBean(ConfirmedType.class) on that mock, not when(StaticHelper.getApplicationContext().getBean(...)) before bootstrap. Inspect the callback: if it only assigns when the static field is null, a second callback will NOT replace the old context. Save the prior context and restore it in @AfterEach/finally; ReflectionTestUtils may reset/restore this exact source-declared non-final ApplicationContext fixture slot. This narrowly scoped lifecycle cleanup is allowed; do not mutate other static/final production collaborators. Each test must work individually and after other tests in the same JVM.
- Prefer a source-supported spy helper seam for ordinary service tests when approved preconditions allow it, to avoid global context state. If the actual target is the lookup method, execute it with the real helper/bootstrap and lifecycle cleanup. Restore RequestContextHolder/SecurityContextHolder/request fixtures after use, preserving prior state when applicable.
- @Spy does not make business logic disposable. Stub only reached helper/inherited persistence boundaries outside the target and private methods. doReturn(...).when(spy)... avoids running the real helper during Arrange. Do not create a plain new SUT after Mockito injection and silently lose injected fields; wire the instance actually used by Act.
- Verify approved observable dependency calls, not incidental bootstrap/getBean access counts. getBean may be called once per helper invocation: count every reached call if an exact count is explicitly approved. Otherwise omit additional verify(context).getBean()/verifyNoMoreInteractions(context) assertions, while retaining ALL approved verifications on the returned collaborator. Do not add verifyNoMoreInteractions(spySut): the real Act call itself is recorded on the spy.
- Optional identity assertions must not invent requirements. If source returns a collaborator's list unchanged, assert the approved contents and required call; never add assertNotSame unless distinct-instance identity is explicitly part of the approved contract. Conversely preserve explicitly approved same-instance/distinct-instance requirements.
- A Spring Security UserDetails implementation does not gain getters for its private wrapped domain entity. Unless its source/Lombok explicitly exposes that getter, verify the approved observable values using the declared UserDetails API (for example getUsername(), getPassword(), getAuthorities(), isEnabled()). A private wrapped field is not evidence of a public get<DomainEntity>() method. Do not add a domain getter assertion just to inspect implementation details. If the approved contract specifically requires an inaccessible wrapped identity, report the precise technical limitation instead of dropping that assertion.
