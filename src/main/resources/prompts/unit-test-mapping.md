# Relevant policy: mapping
- Do not use `assertSame` for mapper, stream, page-map, or newly constructed DTO results; assert observable fields instead. When the SUT calls a private in-class enrichment/mapping helper (even if `preconditions` carries an `UNRESOLVED_HELPER_PATH` note), trace the helper body in the supplied class source and never invent an unapproved `null` assertion (such as `assertNull(result.getPatientName())` or `assertTrue(result.getPatientName() == null)`) on a field populated by that helper from stubbed non-null collaborators.
- For a stateless mapper with a concrete, verified constructor, prefer a real mapper passed to the SUT constructor, or a real initialized `@Spy` collaborator for `@InjectMocks`. If a mapper is `@Mock`, explicitly stub each mapping call on the exercised path with a DTO/entity retaining all asserted fields; `@Mock` does not execute the mapper implementation. Do not invent MapStruct implementation classes or factories absent from context, and do not bypass a real mapper defect by changing approved inputs or outcomes.
- Approved fixture roles take precedence over generic @Mock setup rules: if preconditions require a real mapper, this is mandatory. Supply a source-supported real initialized @Spy for @InjectMocks or pass a real mapper explicitly; never repair a missing real mapper by adding @Mock or stubbing its mapping output.
- An approved prerequisite explicitly requiring a real collaborator is mandatory: use that real instance or a real initialized `@Spy`, including when the result is a mapped list. Do not substitute `@Mock` for it, even when other cases use mocks.
  * REPOSITORY RETURN IDENTITY: `when(repository.save(...)).thenReturn(savedEntity)` returns that exact fixture; Mockito does not copy request/submitted entity fields into it or run persistence callbacks. If production maps the save result into a DTO, trace every asserted DTO field back to savedEntity, not to the request or the entity passed to save. Populate every required returned field through source-confirmed APIs, including generated IDs/timestamps when asserted; an abbreviated mock description is not evidence that omitted fields must be null.
  * For a scenario requiring request-to-entity propagation, prefer a source-compatible `thenAnswer` that returns `invocation.getArgument(0)` after assigning only simulated persistence-generated fields. Keep the production-mapped fields intact so removing a production mapping still fails the assertions. If save must return a separate fixture, populate it consistently and also verify the submitted entity fields with an `ArgumentCaptor` when propagation is the behavior under test.
  * When testing a specific request-to-entity mapping and the approved preconditions leave the old field value unspecified, set the existing entity field to a value different from the approved request. For example, if the approved request enables a flag and the entity defaults to true, initialize the existing entity flag to false through its verified setter. Keep approved request values and assertions. Preserve explicitly fixed old states and idempotence scenarios; never change them merely to make a fixture different.
  * Preserve the approved expected result and null-input scenario. Never replace a required non-null field assertion with assertNull, remove it, or change production to accommodate an incomplete save-return fixture. Use generation_error only for missing/incompatible technical evidence; if current behavior contradicts the approved expected result, retain that business assertion so the test exposes the defect.
- Stubbing Mappers: For an @Mock mapper, stub the mapping methods actually reached with matching arguments and complete return fixtures so the service does not receive null. Execute plain real or initialized @Spy mappers normally; do not apply when(...).thenReturn(...) to a plain real mapper. Preserve source mapper behavior and the approved input/output assertions.
