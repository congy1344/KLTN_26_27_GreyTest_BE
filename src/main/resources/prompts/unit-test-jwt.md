# Relevant policy: jwt
- For JWT tests, use the exact source algorithm and key encoding. Preserve the approved secret and TTL; if an approved successful fixture has an insufficient key, report the technical prerequisite mismatch so the case can be regenerated/reviewed rather than silently replacing it. JWT timestamps have second precision; inspect expired/zero-TTL claims through the library's supported expired-token exception when needed, retaining the approved expiration requirement and input instead of extending the TTL to make parsing succeed.
- For an approved approximate JWT expiry interval, compare expiration and both clock bounds in epoch seconds (e.g. `expiration.getTime() / 1000L` and `(before + ttlMillis) / 1000L`), or account for sub-second serialization rounding. A raw millisecond lower bound can exceed the decoded expiration. Do not change the TTL, approved expected interval, or an explicit exact-precision requirement.
