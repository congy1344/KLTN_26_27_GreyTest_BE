# Relevant policy: collections
- For an approved unmodifiable List with a nonempty approved fixture, assert that set(0, result.get(0)) throws UnsupportedOperationException as well as checking structural mutation. Arrays.asList blocks add/remove but still permits set. Preserve approved empty inputs; do not make an empty scenario nonempty just to perform this check.
- Preserve every input in multi-scenario test_data cases, including repeated IDs. Use consecutive stub returns when the same call must return different results; never invent a second ID to simplify stubbing.
- If the approved result requires collection membership and size without specifying order, assert membership and size. A HashSet, Set or Collectors.toSet() does not establish an iteration order; do not add list-order assertions or reorder approved inputs to match an observed iteration. Preserve an explicitly approved ordering requirement, even when it exposes a source defect.
- For stream pipelines, derive optional Mockito verification counts from each matching input reaching the collaborator call, including calls in `this::helper` mappings. Enrichment before `distinct()` still runs for duplicate inputs; an output size of one does not imply one remote call. Two identical `verify(mock).method(id)` statements each demand one total invocation; they do not consume separate calls. Use one `verify(mock, times(n)).method(id)` when n matching calls are proved. Account for filters and short-circuit operations. If the approved rule/plan/case explicitly specifies a count, retain that count even when source differs so the test exposes the defect.
- MUTATION ORDER AND MATCHERS: trace remove/reverse/sort and pagination trimming in source order before enrichment. Use mutable ArrayList fixtures when production mutates a list, keep independent expected-order copies, and stub each collaborator with the order at its actual call site. Never assume that reversing IDs and reversing returned entities occur at the same point. Derive favorite/following membership IDs directly from the same fixtures and helpers; do not mix different ID prefixes or reuse a list being mutated as the sole proof of expected order.
- COLLECTION ENTRY POINTS: when selecting a public route returning a collection for a private-helper case, stub the repository collection with the approved entity before extracting an element. Mockito's default empty list makes `.stream().findFirst().orElse(null)` null and prevents enrichment from running. Configure every downstream client consumed for that entity too; keep approved IDs, collection contents and assertions, including intentional empty/fallback scenarios.
