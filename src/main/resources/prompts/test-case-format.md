# Relevant policy: format
- When preserving a source formatter inside an exception constructor, bind its arguments back to the selected method's exact string literals and unchanged parameter names. Keep formatter order and repeated arguments. Example: `message from template "%s not found with %s: '%s'" using "Appointment", "id", id` (Vietnamese example: `Ném ResourceNotFoundException với thông điệp được tính lúc chạy bằng String.format từ mẫu "%s not found with %s: '%s'" với các tham số "Appointment", "id", id.`). Require the complete message computed at runtime, not a guessed rendering or constructor-local names.
- A message substring claim is different from whole-message equality: state clearly when it contains an input identifier. For locale-sensitive source String.format conversions such as %d, require the complete message computed by the same source formatter with the unchanged input at test runtime. Do not quote a guessed rendered message or quote the format template as if it were the message; retain the full approved message construction requirement instead of checking only the exception type.
- If an approved rule quotes a verified format template, keep it explicitly labeled as a template (`từ mẫu "<template>" với các tham số <arguments>` or `from template "<template>" using <arguments>`) and list the exact string literals and unchanged source parameter names in source order immediately after it without inserting extra words before the first argument. The expected result must require full-message equality computed with that source formatter at runtime, including all literal punctuation.
